# 前端全面优化计划

更新：2026-09-22。目标是让用户清楚看到已经保存的数据、找到需要的演员、定位资料缺项，并理解对应采集任务为什么尚未完成。视觉方向统一为暖白底色、青绿主色、克制的卡片和清晰的信息层级。

本次提供真实数据驱动的静态交互样稿，作为布局、文案和操作流程的评审依据。正式应用接入、服务端执行任务、资料编辑和审核持久化列入后续实施范围，不能用样稿交互代替这些能力。

## 1. 当前基础与问题

当前真实数据来自 [全量演员采集工作区](./ACTOR_FULL_COLLECTION.md)，与原有 [合成演示](./collection-demo/README.md) 是不同的数据范围。

| 数据项 | 当前数量或状态 | 界面表达要求 |
| --- | --- | --- |
| 已保存演员 | 4,196 位 | 使用来源身份键去重；同名不能直接合并 |
| 本地普通头像 | 130 张，覆盖约 3.1% 的演员 | 与没有头像的演员使用相同资料层级 |
| 缺少头像 | 4,066 位 | 提供直接筛选入口，不能用无关图片填补 |
| 别名、简介、生日、身高 | 各有 4,196 位尚未取得 | 明确显示“尚未记录”，不推断为没有、不填 0 |
| 采集任务 | 共 4,414 项：完成 2、阻塞 2、待处理 4,410 | 区分队列进度、字段覆盖和全站覆盖 |
| 已采作品详情 | 0 条 | 列表作品数只是来源列表计数 |
| 来源访问 | Jable 后续返回 403，JavDB 连接重置 | 展示最后一次记录及时间，不显示为实时健康 |

上述数量是当前批次基线。实际界面统计应从导出文件和持久队列计算，并显示快照时间，不能继续写成固定常量。数据依据为本机 `runtime/actor-collection/20260922-full/collection-summary.json` 和 `runtime/actor-collection/20260922-full/task-report.json`；这些报告由采集流程生成，不随代码提交。

| 现状问题 | 具体证据 | 对用户的影响 |
| --- | --- | --- |
| 默认工作台围绕合成作品组织 | [原工作台模板](../scripts/templates/collection-demo.html) 的 `state`、`dashboard()`、`catalog()` 使用 24 条初始作品、36 个合成实体；[构建器](../scripts/build_collection_demo.mjs) 读取 fixture | 用户难以从主入口判断实际采集了什么 |
| 真实演员库与任务工作台分离 | [演员库模板](../scripts/templates/jable_performers.html) 只提供搜索、头像筛选和保存信息详情 | 查看缺项后没有通往对应任务和来源的连续操作 |
| 大量空头像占据主要空间 | 4,066 位缺头像；原演员模板使用方形大图卡片 | 大多数卡片视觉重复，姓名和已知字段的信息密度偏低 |
| 全量 DOM 与输入重渲染 | 原演员模板 `render()` 每次把所有匹配演员映射为 HTML；图片未设置懒加载 | 数据量增长后，首屏和连续输入更容易受影响，需实际测量 |
| 界面任务不是持久队列 | [原任务管理脚本](../scripts/templates/collection-management.js) 读取 `localStorage`，只运行 fixture 或保存浏览器计划 | 界面看起来有任务，却无法反映现有的 4,414 项真实任务 |
| 导航和筛选状态不可完整恢复 | 原工作台 `navigate()` 使用 `replaceState`，查询、排序和类型主要存在内存中 | 后退、刷新和分享链接不能可靠回到相同结果 |
| 辅助信息字号和对比度不足 | 原工作台大量信息为 9–11px；代码色值计算得到 `#7c8390`/白底约 3.81:1、表头 `#959ca6`/`#fafbfc` 约 2.67:1 | 状态、说明和表头阅读成本偏高 |
| 测试对真实用户旅程覆盖不足 | [原演员浏览测试](../scripts/test_jable_showcase.mjs) 要求全量卡片同时存在；[原工作台测试](../scripts/test_collection_demo.mjs) 主要验证合成流程 | 现有测试通过不代表真实任务接入、分页或无障碍合格 |

原工作台已有跳转主内容、部分焦点样式、转义和浏览器配置保存等基础，可以复用。深色演员页的主要正文对比度较好，改进重点是统一视觉、提升字号及建立完整流程。

## 2. 用户旅程与五个入口

优先支持两类实际任务：查资料的人需要快速找到演员并核对已知信息；维护数据的人需要定位缺项、辨认阻塞原因和核对补采结果。

主要旅程为：**概览 → 演员资料 → 演员详情 → 对应补全任务 → 来源状态**。维护旅程为：**资料缺项 → 按字段筛选演员 → 导出清单 → 核对采集任务 → 回看新增信息**。

| 入口 | 第一屏回答什么 | 主要内容与操作 | 关联去向 |
| --- | --- | --- | --- |
| 概览 | 保存了多少，哪些问题影响继续采集 | 演员、头像、待处理和阻塞数量；来源问题；字段覆盖；少量真实资料 | 点击指标进入相应筛选，查看来源问题 |
| 演员资料 | 能否找到指定演员，已经知道什么 | 搜索、头像筛选、排序、48 条分页、卡片/列表、详情、导出 | 缺项标签与该演员任务 |
| 资料缺项 | 哪些字段最需要补充，涉及哪些演员 | 各字段缺项数量、对应演员入口、缺项清单导出 | 保留字段条件进入演员列表 |
| 采集任务 | 哪些已完成、待处理或阻塞 | 来源和状态筛选、类型、尝试次数、最后记录、任务详情、导出 | 对应来源及演员；正式接入后提供有效的执行操作 |
| 来源状态 | 什么阻止继续获取数据 | 最近访问结果、检查时间、已保存演员、受影响任务、可读错误说明 | 进入该来源任务列表 |

“项目蓝图”、架构说明和合成演示保留独立入口，放入开发文档或次级帮助区域。真实数据主导航不增加暂时没有实际资料的作品、厂牌等一级栏目。

## 3. 视觉与组件规范

整体使用轻量资料工作台风格：页面暖白、内容卡片纯白、正文偏深绿灰，青绿突出可执行动作。琥珀色只表达需要关注的状态，危险色用于失败或有影响的变更。每个区块尽量只设置一个主要动作。

| Token | 建议值 | 使用位置 |
| --- | --- | --- |
| 页面背景 `--bg` | `#f5f5f0` | 页面底色和留白 |
| 内容背景 `--paper` | `#ffffff` | 卡片、表格、输入区域 |
| 正文 `--ink` | `#252e2a` | 姓名、标题、主要数据 |
| 辅助文字 `--muted` | `#656e68` | 说明、时间、次级元数据 |
| 边界 `--line` | `#e1e5dc` | 细分隔线与卡片边框 |
| 主色 `--accent` | `#246c55` | 主要按钮、链接、选中状态 |
| 主色浅底 `--soft` | `#eaf3ec` | 当前导航、切换状态 |
| 注意状态 | `#946020` / `#fbf2e3` | 来源阻塞、待补字段 |
| 失败状态 | `#a64b38` | 明确失败提示，搭配文字 |
| 间距 | 4、8、12、16、24、32px | 控件、分组、页面边界 |
| 圆角 | 控件 7–9px，卡片 12–14px | 保持一致，避免所有元素圆成胶囊 |

正文以 14px 为基准，主要标题 26–30px，区块标题 16–18px，关键指标 30–34px；常用辅助信息目标不小于 12px。少量装饰性英文标识可以更小，但不能承载必要状态。正式组件需逐项检查字号，样稿中的局部小字号不能直接成为生产规范。

普通文字对比度目标至少 4.5:1。主按钮、状态文字、边框和焦点环按实际前景/背景组合检查，不能只验证一组 token。头像使用真实本地文件，明确宽高；列表缺图采用小尺寸姓名字形占位，不生成替代人物照片。阴影只用于浮层，卡片主要依靠边框和留白区分。

正式实现建议拆分为导航壳、指标卡、来源状态、搜索筛选、演员卡片/列表行、缺项标签、状态标记、分页、详情抽屉、空状态和导出反馈组件。共享格式化与状态映射，数据接入放在独立适配层；继续复用项目或正式宿主已有技术栈，不为静态样稿引入不必要的框架。

## 4. 关键交互与数据语义

| 场景 | 交互要求 | 可验收行为 |
| --- | --- | --- |
| 搜索 | 姓名、已取得的别名和来源 ID；NFKC 归一化；支持中文输入法组合输入 | 输入组合过程中不抢焦点；输入结束更新；空格和全角等价查询合理；无结果有清除入口 |
| 分页与排序 | 演员和任务默认每页 48 条；显示区间、总数、当前页；排序稳定 | 改筛选回第 1 页；末页无遗漏；上一页/下一页禁用准确；同值排序有稳定身份键兜底 |
| 头像视图 | 默认有头像优先，同时保留所有演员；可切换紧凑列表 | 130 张头像与 4,066 位缺头像分别可筛选；视图切换不丢失搜索与页码 |
| 详情 | 桌面右侧抽屉，手机整屏；先展示姓名、来源、别名、列表作品数和时间，再显示缺项 | 查看保存记录和任务无需离开当前资料上下文；关闭后回原入口 |
| 缺失语义 | 区分尚未取得、来源明确未提供、历史下载失败和未知；只有证据支持时才细分 | 不把 `null`、空字段转成 0；真实的计数 0 正常显示；无证据时统一标记“尚未记录” |
| 来源状态 | 快照与实时状态分开，明确时间和来源 | HTTP 403 与连接重置可读；“未阻塞”不能被误写为当前可访问 |
| 任务状态 | pending、running、completed、blocked、failed 按服务端事实映射 | 完成页数不当作全站覆盖；阻塞任务数不当作受影响任务数 |
| 导出 | 当前演员结果、缺项清单、当前任务；包含数量与快照时间 | 导出全部匹配记录，不只当前页；内部搜索缓存不进入文件；结果数与界面一致 |
| 路由恢复 | 搜索、筛选、来源、排序、布局、页码进入 URL，返回恢复滚动；正式版增加详情 ID | 刷新及前进/后退恢复正确状态；未知参数使用合理默认值，不渲染异常页面 |
| 状态反馈 | 浏览状态、筛选无结果、加载失败、过期快照和导出完成分别表达 | 错误就近可见；失败后保留输入；正式网络版本可重试而不重复写入 |

头像数量以文件存在、格式和尺寸有效、校验一致为依据。身份沿用 `(source_id, external_id)`；跨来源同名只能作为候选关系，不能自动覆盖既有演员。逐字段来源、检查时间和解析器证据应保留在数据层，详情中渐进展开，避免把文件 hash 等工程信息放到资料卡主位置。

## 5. 响应式、无障碍与性能要求

桌面保留完整侧栏；中等宽度可以收起侧栏文字但必须保留可访问名称；手机使用五入口底部导航。页面底部留出导航和设备安全区域，抽屉关闭按钮不能被底栏遮挡。验收覆盖 320、390、768、1024 和 1440px 宽度，检查长姓名、长来源 ID、空结果、任务详情和表格。

主要移动控件点击区域目标至少 44 × 44px。表格允许容器内部横向滚动，整页不横向溢出；每行的任务身份、状态和详情入口应容易定位。缩放到 200% 后必要内容和操作仍可达。

导航使用链接并标记当前页；切换按钮使用 `aria-pressed` 或合适的控件语义；搜索和下拉框有可访问名称；结果计数以温和的 live 区域更新。抽屉关联标题、支持 Esc、焦点受控且关闭后返回入口。所有可操作控件有清晰焦点环，支持减少动态效果偏好。正式表单错误绑定字段并保留，不能只显示几秒 toast。

性能先通过限制渲染规模解决：单次演员与任务列表最多 48 条，头像懒加载并预留尺寸，搜索索引只计算一次。正式应用使用服务端分页或游标和稳定排序，详情按需读取。只有性能测量表明必要时才引入虚拟列表，避免增加键盘和读屏复杂度。

性能验收需记录浏览器、设备、数据规模和是否采用 CPU 降速。建议目标是在 4,196 位演员、4,414 项任务的基线上，本地搜索到结果完成绘制的 P95 不高于 200ms，分页和详情在 200ms 内反馈；以同一测量方法复核。首屏加载、DOM 节点数、长任务和内存同时保存基线。上述是目标值，不能在未测量时写成已通过。

## 6. 本次静态样稿与后续边界

样稿源码为 [frontend-preview.html](../scripts/templates/frontend-preview.html)，构建脚本为 [build_frontend_preview.py](../scripts/build_frontend_preview.py)。默认从 `runtime/actor-collection/20260922-full/` 读取导出与只读队列，输出到独立的 `runtime/frontend-preview/20260922/`，不覆盖原归档或原演示。

```bash
node scripts/run_python.mjs scripts/build_frontend_preview.py \
  --work-dir runtime/actor-collection/20260922-full \
  --output-dir runtime/frontend-preview/20260922
```

生成目录包含 `index.html`、`dataset.json`、`build-report.json` 和本地 `media/`。打开生成的 `index.html` 可评审交互。更新资料后需要重新构建，界面不自动联网更新。

使用默认工作区时也可直接运行 `npm run build:frontend-preview`。安装项目浏览器测试依赖且本机有 Chrome 后，运行 `npm run test:frontend-preview`，可重现 [浏览器旅程验收](../scripts/test_frontend_preview.mjs)。构建依赖本机已有数据，克隆仓库不会自动获得 `runtime/` 中的资料。

| 本次已有样稿实现 | 当前边界 |
| --- | --- |
| 五入口导航、暖白与青绿视觉、响应式布局 | 独立设计预览，不代表已替换正式应用 |
| 真实演员、头像、队列和来源状态快照 | 快照来自已有采集结果，不新增在线数据 |
| 搜索、IME 处理、头像筛选、排序、48 条分页、卡片/列表切换 | 正式服务端分页、索引和超大数据量性能尚待实施 |

简介、生日、身高及精简逐字段来源已进入数据投影和详情：当前未取得的值保持为空，已有来源链接和观察时间可展开查看。逐字段差异对比、历史证据和审核裁决列入正式数据适配。原有 [合成工作台](./collection-demo/README.md) 继续作为独立演示；其中浏览器保存的网站和计划不会变成真实采集队列。

## 7. 分阶段实施

以下优先级围绕正式化交付排序。人日仅为已有数据与采集脚本可复用前提下的估计，不是上线日期；接口工作单列，不能包含在“改前端样式”中。

| 阶段 | 具体交付内容 | 依赖 | 验收标准 | 前端估计 |
| --- | --- | --- | --- | --- |
| P0：真实入口与设计基线 | 固定五入口、视觉 tokens、真实快照适配、概览、演员分页/搜索、缺项语义、队列与来源只读视图 | 已有 JSONL、tasks.db、报告；本次样稿 | 统计与当前工作区一致；原演示独立；任意列表不全量铺开；无虚假的执行成功；长名称与空状态可读 | 3–5 人日 |
| P1：完整浏览体验 | 稳定路由与返回恢复、细分筛选、列表/详情联动、完整档案字段和证据、JSON/CSV 导出、共享组件、键盘/手机适配 | P0；只读数据合同；真实字段语义 | 从缺项到演员再到任务可连续完成；筛选导出一致；浏览历史正确；主要控件、焦点和字号达到规范；性能有基线和结果 | 5–8 人日 |
| P2：正式操作流程 | 在真实接口就绪后接入任务创建/重试/取消、资料编辑、字段裁决和审核结果；状态反馈及异常恢复 | P1；执行、编辑及审核接口；既有权限和版本合同 | 状态以服务端提交结果为准；失败保留输入；重复提交幂等；刷新不丢结果；版本冲突不会静默覆盖 | 4–7 人日 |

正式前端合计约 12–20 人日，包含对应交互验收与回归；API 开发、采集来源恢复和内容补采不计入。P2 只有在相应接口与业务规则具备时才可交付，来源网络恢复时间不能由前端工期承诺。

| 服务端/API 工作包 | 需要明确的能力 | 前端依赖 | 单独估计 |
| --- | --- | --- | --- |
| 只读资料与任务 API | 分页、稳定排序、组合筛选、详情、字段证据、统计、快照/版本标识、导出 | 正式在线 P0/P1 | 2–4 人日 |
| 执行任务 API | 创建或关联任务、重试/取消、幂等键、来源停止规则、状态更新、错误映射 | P2 任务操作 | 3–5 人日 |
| 资料编辑与补全 API | 字段级更新、证据引用、版本校验、变更记录、并发冲突返回 | P2 编辑 | 4–7 人日 |
