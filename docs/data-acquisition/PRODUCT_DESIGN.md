# 资料展示与采集工作台设计

## 1. 产品目标

让访客用番号、标题、人物或厂牌定位作品、确认基本身份、沿关系继续浏览。采集系统负责稳定提供候选，运营系统负责判断正确性与发布资格。不要把“本轮抓到多少条”直接等同于“网站新增多少条”。

首批展示以文字资料为主：番号、标题、发行日期、厂牌、人物、别名、资料更新时间。图片缺失时用现有默认图；本轮原型使用 CSS 绘制的抽象编号封面，不生成真实图片资产记录。

## 2. 信息架构与页面

| 页面 | 首要任务 | 关键操作 | 必须准确的状态 |
| --- | --- | --- | --- |
| 工作概览 | 识别供给瓶颈 | 运行样例、进入资料列表 | 预置展示、待处理、冲突、真实来源可用量分开 |
| 采集任务 | 创建有界批次、处理失败 | 创建、运行、取消、重试、日志 | 候选接收完成不等于发布完成 |
| 来源管理 | 决定哪个来源可进入试运行 | 查看角色、规则、字段、探测证据 | 未核验不能显示健康或可运行 |
| 候选审核 | 判断字段与关系 | 对照证据、选择冲突值、确认、退回 | 缺标题不可发布；未知日期允许保留为空 |
| 资料预览 | 搜索与身份确认 | 类型切换、排序、详情、复制番号、关联查询 | 只包含预置展示资料和本机已确认记录 |
| 项目蓝图 | 看懂责任与实施顺序 | 查看链路、里程碑、字段责任 | 目标设计与已实现内容分开 |

六页在一个离线 HTML 内切换，支持 hash 直达。工作台导航属于设计演示外壳；实际访客公开站不出现任务、审核、来源管理导航。资料详情不展示内部来源、审核人员、队列或置信度。

新增网站与任务配置已加入演示：来源管理支持域名登记和字段选择，任务表单按所选来源切换为 fixture 场景或网站计划。网站计划保存为待接入状态，刷新后保留在当前浏览器；真实抓取与跨机器同步需后端集成。见[交互规则](./WEBSITE_TASKS.md)。

## 3. 展示设计

查询入口优先，作品列表保留番号、标题、厂牌与发行日期。作品详情先身份、再关联，不依赖封面识别。较长标题在卡片截断，详情完整显示。无日期明确写“未知”，最新发行排序把无日期放末尾；资料更新与发行日期分别表达。人物与厂牌有独立结果，可继续查看关联作品。

视觉使用暖灰背景、白色信息面板与少量橙色操作按钮。橙色表示当前动作或待核验，绿色表示本机样例就绪 / 已确认，不能用颜色代替状态文字。数据表在手机局部滚动，导航横向滚动；搜索、弹窗与卡片支持 320px 宽度。所有核心动作可用键盘操作，弹窗具备标题、关闭按钮和原生焦点约束。

## 4. 数据操作路径

1. 选择已登记的来源、固定连接器版本、区域、范围与预算。试运行从手动任务开始。
2. Worker 完成候选接收后显示输入、唯一观测、拒绝、重复、实体候选数量，提供错误原因。
3. 来源记录保留事实，不覆盖公开版本。冲突给出每个字段的候选值和证据。
4. 编辑提出资料版本，独立审核者确认。人物关系、成年确认和媒体权利延续现有审核约束。
5. 发布服务写入正式版本；异步缓存更新完成前，后台应区分“发布已提交”和“公开可见已确认”。

演示中的两个身份是合成标签，确认按钮只改变内存 Set，不具有真实认证、发布事务、权利核验或缓存更新能力。

## 5. 内容样本与异常覆盖

固定样本有 36 个作品实体、8 个虚构人物、4 个虚构厂牌。43 条输入经过同源去重留下 40 条唯一观测：其中 2 个实体有第二来源一致证据，2 个实体有冲突证据。预置展示 24 条；剩余 8 条普通候选、2 条日期冲突、2 条标题缺失。另有 2 条日期未知、多人物和长标题样例。

演示可实际操作：首轮运行、重复提交不增加实体、超时后重试、结构变化停止、取消待运行任务、字段裁决、退回、未确认禁止加入预览、无结果、关系跳转和结果导出。正式产品的权限异常、跨区故障、账号续接、反馈与下架使用既有应用测试，并在 Release B 接入时补联合验收。

## 6. 衡量方法

资料完整率以“非空字段数 / 适用字段数”计算，未知值不伪造。真实准确率必须使用独立人工标注样本计算；不能从 fixture 的完整度或置信度推导。优先跟踪来源可用、候选重复、冲突积压、审核耗时、发布延迟和按实体划分的查询成功情况。不要用重复轮询提高资料更新时间或新增量。
